# 出库单 Invoice No 查重 — 前端对接说明

## 背景

后端在**保存出库单**前增加了 **Invoice No（`invoice_no`）** 的应用层查重：同一门店下，非空发票号不能与已有出库单重复。数据库**未**加唯一约束，校验仅发生在下列接口调用时。

前端需在创建/编辑出库单、以及出库申请审批生成出库单时，识别新的业务错误码并给用户明确提示。

---

## 业务规则（与后端一致）

| 规则 | 说明 |
|------|------|
| 查重范围 | 当前登录用户所属 **门店**（`store_id`，创建时由后端从 token 写入） |
| 参与查重的字段 | 请求体中的 `invoice_no` |
| 空值 | `null`、未传、`""` 或仅空白字符 → **不查重**，允许保存 |
| 非空值 | 与同门店任意一条出库单的 `invoice_no` **完全一致**（后端会对输入做 `trim` 后比对）即视为重复 |
| 更新自身 | 编辑时若 `invoice_no` 未改或仍为本单原值 → 通过 |
| 作废/状态 | **不**因 `isVoid`、`status` 等排除记录；已硬删除的单据不再占用号码 |
| 并发 | 极端并发下仍可能出现重复落库；前端按接口返回处理即可 |

---

## 涉及的接口

### 1. 创建出库单

- **Method / Path:** `POST /outbound-orders/create`
- **Body:** 与现有一致，含可选字段 `invoice_no`（最长 50）

### 2. 更新出库单

- **Method / Path:** `POST /outbound-orders/:id`
- **Body:** 与现有一致；若本次修改包含 `invoice_no`，会参与查重

### 3. 审批出库申请（生成出库单）

- **Method / Path:** `POST /outbound-request/approve/:id`（以实际路由前缀为准）
- **说明:** 审批时会用申请单上的 `invoice_no` 创建出库单，同样查重

---

## 响应格式

本模块沿用项目统一的 `RESULT_CODE` 包装（HTTP 仍为 200，以 `code` 区分成败）。

### 成功（无变化）

```json
{
  "code": 0,
  "data": { ... }
}
```

### Invoice No 重复（新增需处理）

```json
{
  "code": 5003,
  "msg": "Invoice No already exists"
}
```

- **常量名（后端）:** `DATA_ALREADY_EXISTED` = `5003`（见 `src/common/other-config.ts`）
- **无** `data` 字段或可为空；不要依赖 `data` 里的明细

### 其他错误（无变化）

例如系统异常仍为 `code: 4001` 等，按现有全局错误处理即可。

## 前端改动建议

### 1. 错误码常量

在现有 `RESULT_CODE` / 错误码枚举中增加（若尚未存在）：

```ts
DATA_ALREADY_EXISTED: 5003,
```

### 2. 统一响应处理

在出库单 **创建、保存（更新）** 以及 **出库申请审批** 的请求回调中增加分支：

```ts
if (res.code === 5003) {
  // 展示用户可读文案，见下方「文案建议」
  return;
}
if (res.code !== 0) {
  // 原有逻辑
}
```

若项目使用 axios 拦截器统一解析 `code`，在拦截器或业务层对 `5003` 做映射即可，避免三处重复写死英文 `msg`。

### 3. UX / 表单

- 在 **Invoice No** 输入框附近展示错误（Toast + 字段级提示二选一或同时使用）。
- **不必**新增单独「校验 Invoice 是否重复」的预检接口；保存/审批时后端会返回 `5003`。
- 可选体验优化：收到 `5003` 后聚焦 `invoice_no` 输入框。
- 空 Invoice No 仍允许提交（业务未强制必填）。

### 4. 文案建议

| 场景 | 中文示例 | 英文（可与后端 msg 对齐） |
|------|----------|---------------------------|
| 创建/编辑保存 | 发票号已存在，请更换后重试 | Invoice No already exists |
| 出库申请审批 | 无法审批：发票号与已有出库单重复 | Invoice No already exists |

建议使用 i18n key（例如 `outbound.invoiceNo.duplicate`），不要长期直接展示后端英文 `msg`。

### 5. 出库申请审批页

审批按钮调用 `approve` 接口后，若返回 `5003`：

- 提示用户修改申请单上的 Invoice No 后再审批，或
- 引导至申请单编辑页（产品自定）

## 测试清单

- [ ] 同门店：A 单 `invoice_no = "INV-001"` 保存成功；B 单相同号码 → `code === 5003`，列表无新单
- [ ] 编辑 A 单不改 `invoice_no` → 成功
- [ ] 编辑 A 单改为 B 单已有号码 → `5003`
- [ ] `invoice_no` 为空或不填 → 成功（可多单）
- [ ] 仅空格 `"   "` → 视为空，不查重
- [ ] 出库申请审批：申请单发票号与已有出库单冲突 → `5003`，不生成新出库单

---

## 不在本次范围

- 进货单 / 入库单 `invoice_no` 查重
- 数据库唯一索引、迁移
- 按作废单排除查重
- 保存前异步「查重专用」API（未提供）

如有疑问或与现网前端 `code` 处理不一致，以后端 `outbound-order.service.ts` 中 `assertInvoiceNoUnique` 及上述三个接口为准。
